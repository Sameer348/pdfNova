# PDFNova — Architecture (Phase 1)

Target: Hostinger **shared** hosting — Apache + `.htaccess`, PHP 8.1+, MySQL/MariaDB.
No Node, Python, Docker, Redis or background daemons are required at runtime.

---

**Optional hardening (recommended):** Hostinger lets you place folders *above*
`public_html` (e.g. `/home/uXXXX/domains/yourdomain.com/pdfnova_private/`).
`config.php` exposes `STORAGE_PATH` and `APP_PRIVATE_PATH`, so `storage/`,
`includes/`, `services/`, `vendor/` can be moved out of the web root with no code
changes. If left inside, the `.htaccess` deny rules protect them.

## 2. Request flow

```
Browser ──GET /merge-pdf──▶ .htaccess ──▶ index.php ──▶ router.php (whitelist)
                                                       └─▶ pages/tool.php + tools.php['merge-pdf']

Tool page JS:
 1. uploader.js  ──POST /api/upload.php (multipart, CSRF)──▶ file_id (random token)
 2. tools.js     ──POST /api/merge.php {file_ids[], options}──▶ processing_jobs row
                                         └─▶ services/pdf/FpdiEngine::merge()
                                         └─▶ storage/processed/<random>.pdf
                 ◀── { success, message, download_url (HMAC-signed, expires) }
 3. Download     ──GET /api/download.php?t=<signed>──▶ ownership + expiry check ──▶ stream
 4. Input uploads deleted immediately after the job; results deleted by cron after TTL.
```

Guests are supported (files tied to the PHP session id); logged-in users get
history in the dashboard (metadata only — file content still expires).

## 3. Library choices (all pure PHP — no server binaries)

| Purpose | Library | Notes |
|---|---|---|
| Read/import PDF pages | `setasign/fpdi` (MIT) + **our extended parser** (`services/pdf/Parser/`) | The free FPDI parser rejects PDF 1.5+ files with compressed cross-references. `PDFNova\Pdf\NovaFpdi` adds cross-reference streams, hybrid files, object streams and PNG predictors (tested: 10/10 previously-rejected real PDFs now import, visually identical). Still cannot open **encrypted** PDFs. Always use `NovaFpdi`, never FPDI directly. |
| Write PDFs, encryption, watermarks | `tecnickcom/tcpdf` (LGPL) | Used as FPDI's base; supports RC4/AES protection. |
| ZIP results | PHP `ZipArchive` (ext-zip) | Enabled on Hostinger by default. |
| Page thumbnails / PDF→JPG rendering | `pdf.js` (browser) | Rendering happens client-side; no Imagick/Ghostscript needed. |
| Client-side ZIP for PDF→JPG | `JSZip` (browser) | Lazy-loaded. |

Composer is run **on your computer** (or over Hostinger SSH on plans that have it),
and the resulting `vendor/` folder is uploaded. Details in Phase 16.

## 4. Honest capability matrix on shared hosting

| Tool | Engine | Works on plain shared hosting? |
|---|---|---|
| Merge, Split, Rotate, Organize | FPDI + TCPDF (server) | ✅ Yes. Note: imported pages keep their visual content; interactive form fields, bookmarks and some link annotations are not preserved. |
| Watermark (text/image) | FPDI + TCPDF | ✅ Yes |
| Protect (password) | TCPDF encryption | ✅ Yes (AES-128/256) |
| JPG/PNG → PDF | TCPDF | ✅ Yes |
| PDF → JPG | pdf.js in the browser | ✅ Yes — rendering happens on the user's device; server is not involved. |
| Compress | Ghostscript if `exec` + `gs` exist, else structural re-write | ⚠️ Partial. Without Ghostscript, real image downsampling isn't possible in pure PHP; the page shows the **actual** resulting size and says plainly if no saving was achieved. External API adapter available. |
| Unlock | qpdf if available, else external API adapter | ⚠️ Pure-PHP decryption isn't provided by any maintained free library. Shows "not configured" until an engine is set up. Wrong-password errors are surfaced from the engine. |
| PDF ↔ Word / Excel / PowerPoint | `services/converters/` adapter | ❌ Not on shared hosting alone (needs LibreOffice or a commercial engine). Ships with a "Not configured" adapter + ready CloudConvert/ConvertAPI adapter that works once an API key is set. |
| OCR | `services/ocr/` adapter | ❌ No Tesseract on shared hosting. Adapter for OCR.space/other API; page states clearly when unavailable. |
| Payments | `services/payment/` adapter | Manual/disabled gateway by default; Stripe stub documented. |

Tool pages whose engine is not configured still render (for SEO) but show a clear
"This tool isn't available yet" notice and a disabled action button — no fake success.

## 5. Security design

- **Routing:** whitelist only; `includes/ pages/ services/ templates/ database/ cron/ vendor/ storage/` denied via `.htaccess`.
- **Uploads:** stored under random 32-hex names with no extension; validated by
  magic bytes + `finfo` + extension allowlist + size; original name kept only in DB
  (escaped on output). `storage/.htaccess` disables PHP and denies all direct access.
- **Downloads:** `api/download.php` with HMAC-SHA256 token (file id + owner + expiry), constant-time compare, `Content-Disposition: attachment`, `X-Content-Type-Options: nosniff`.
- **Auth:** `password_hash()`/`password_verify()`, `session_regenerate_id(true)` on login, cookie flags `HttpOnly`, `Secure`, `SameSite=Lax`, idle + absolute timeouts, hashed single-use reset tokens (60 min).
- **CSRF:** synchronizer token on every form and every POST API call (header `X-CSRF-Token`).
- **XSS:** `e()` escaping helper on all output; CSP header.
- **SQL:** PDO with `ATTR_EMULATE_PREPARES=false`, prepared statements only.
- **Rate limiting:** MySQL-backed (`rate_limits` table) per IP/user for login, register, reset, upload and processing.
- **Quotas:** per-plan max file size, files per job, jobs per day — enforced server-side.
- **Cleanup:** `cron/cleanup.php` every 15 min deletes uploads > 1 h, results > 2 h, temp > 30 min, expired resets & rate-limit rows. Request-time fallback cleanup runs occasionally in case cron isn't configured.
